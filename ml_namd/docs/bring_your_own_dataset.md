# Bring your own dataset

The pipeline is **molecule-agnostic**: nothing in the training, genA, composed-FSSH, or harvest code is
specific to acetylacetone. The two worked examples (`../examples/{enol,keto}/`) are acetylacetone because
that is what the shipped data covers, but you can run the same pipeline on any system once you provide the
arrays below and set a handful of per-system values. This guide lists what to provide, what to change, and
the invariants that must hold for any system.

---

## 1. What you provide (the `acn_` array contract)

All data is plain NumPy `.npy`, one array per quantity, with the `acn_` prefix and the frame index as the
leading axis. Full schema + dtypes are in `../data_manifests/DATA_MANIFEST.md`. For a system with
`n_at` atoms and excited states `S1..SK` (coupling pairs `P`):

**Model A pool** (energies + forces):
- `acn_R` `(N, n_at, 3)`, `acn_Z` `(N, n_at)`, optional `acn_V` `(N, n_at, 3)`
- `acn_sE0 .. acn_sE{K}` `(N,)` -- per-state **shifted** energies (`sE = E_raw - E0`, with `E0` a fixed
  reference energy for your system)
- `acn_F0 .. acn_F{K}` `(N, n_at, 3)` -- per-state forces

**Model B pool** -- the same pool, plus, per coupling pair `ij`:
- `acn_dENACR{ij}` `(N, 3*n_at)` -- the **target** scaled coupling (reference/oracle), flattened
- the **input** `acn_GDV{ij}` / `acn_GAP{ij}` are **not** supplied by you: the genA step
  (`../scripts/data_generation/gen_modelA_inputs.py`) writes them from the frozen Model A's predictions
  (so training matches inference). You only provide the oracle `dENACR` target + the E/F that Model A learns.

**Initial conditions** (for FSSH): matched per-IC `R0` / `V0` / `Z` `.npy` arrays. The FSSH@PYSEQM
reference also needs the same ICs in its `coords.xyz` + NEXMD `velocity.out` form (see `fssh_pyseqm_guide.md`).

## 2. What to change for your system

Per-system settings live in the config (generated by `../scripts/training/tools/config_gen.py`, or written
by hand from the minimal template in `model_b_usage_guide.md`):

| Setting | What it is | Example (acetylacetone) |
|---|---|---|
| `n_atoms` | atoms per frame | `15` |
| `possible_species` | atomic numbers present | `0 1 6 8` (0 = padding) |
| `n_states` | number of **excited** states | `3` (S0-S3) |
| `targeted_scaled_nacr_pairs` | the coupling pairs Model B learns | `12 13 23` |
| `dist_soft_min` / `dist_soft_max` / `dist_hard_max` | HIP-NN radial cutoffs (A) | `0.7 / 5.68 / 11.83` |
| `n_features`, `n_sensitivities`, `l_max`, `n_max`, ... | network capacity | nf145 defaults |
| `learning_rate`, `batch_size`, `max_epochs`, `l2_weight` | optimization | see the SPEC |
| `state_nacr_weights` (optional) | up-weight a near-degenerate pair | keto only: `12:4.0` |

Plus, outside the config:
- **Energy shift `E0`** -- choose a fixed reference energy and build `acn_sE{k} = E_raw - E0` when you make
  the pool (a data-prep step; see `../data_manifests/DATA_MANIFEST.md`).
- **Stratification pair** -- `make_split_masks.py` stratifies the train/valid/test split on `|GAP12|`
  (the near-degenerate pair). If your system's near-degeneracy is a different pair, set `GAP_FILE` in
  `make_split_masks.py` accordingly (or use `--split random` if no near-degenerate stratum matters).
- **Atom ordering** -- the FSSH@PYSEQM reference driver sorts atoms by **descending atomic number**; keep
  your `acn_Z` order consistent across the pool, the models, the ICs, and the harvest.
- **Dynamics length / IC prefix** -- in an example's `_common.py`: `NSTEPS` (steps = ps / timestep) and
  `IC_PREFIX`.

## 3. How to run it

The quickest path is to copy an example directory as a template:

1. Copy `../examples/enol/` to `../examples/<your_system>/`.
2. Edit `_common.py`: set `TAUT` to your system name, `IC_PREFIX`, and `NSTEPS`.
3. Put your arrays under `data/<your_system>/balf/` and your ICs under `ics/` (matching `IC_PREFIX`).
4. Point the config at your system's settings. `config_gen.py` bakes in the acetylacetone SPEC + the
   enol/keto layout; for a different molecule either (a) edit the SPEC/`possible_species`/`n_atoms`/
   `n_states`/pairs in a copy of `config_gen.py`, or (b) write the `.inp` directly from the minimal
   template in `model_b_usage_guide.md` and call `run_train_rndsplit.py` yourself.
5. Run `02_train_model_A.py` -> `03_train_model_B.py` -> `04_run_ml_tsh.py` -> `05_harvest.py` as in the
   example READMEs.

The step scripts, `run_train_rndsplit.py`, `gen_modelA_inputs.py`, `namd_composed_batch_perIC.py`, and
`harvest_topo.py` are all system-independent -- they read `n_atoms` / `n_states` / pairs from the config and
the array shapes from your pool.

## 4. Invariants that hold for every system

These are not acetylacetone-specific; respect them whatever the molecule (details in the stage guides):

- **train-A == deploy-A.** Model B must train on the frozen Model A's predicted GDV/GAP (the genA step),
  and the Model A you deploy in FSSH must be that same checkpoint. `gen_modelA_inputs.py` stamps
  `genA_source.json`; `fssh_provenance.py assert` enforces it before a run. Keep the A-predicted GDV/GAP in
  a directory with no reference copies, or the loader silently reads the reference values.
- **Raw gap, no floor.** The derivative coupling divides by the raw adiabatic gap with no floor/clamp
  (flooring inverts small gaps and NaNs the amplitudes). See `fssh_mlip_guide.md`.
- **Reference method is fixed.** FSSH@PYSEQM uses `hamiltonian_fd` TDC + `decohere_on_hop=True`; the MLIP
  uses `nac_dot_v`. Compare like-for-like (same ICs, manifold, initial state, timestep, survivor
  conditioning) and report both survivor-conditioned and original-N normalizations.
- **Per-IC seeding.** Seed each initial condition `base + global_index` (one hop draw per step), matching
  the reference, via `namd_composed_batch_perIC.py` -- not one fixed seed per batch.
- **Guarded harvest.** `harvest_topo.py` drops non-survivors, NaN-amplitude trajectories, exploded
  geometries (peak pair-distance > max-dist), and fragmented trajectories; report the yield.
- **float64 inference** with custom kernels off (`HIPPYNN_USE_CUSTOM_KERNELS=False`).

## 5. Minimal smoke

Before a full run on a new system: train Model A + Model B for 2 epochs (set `max_epochs = 2` in the
config) on a small slice, run `04_run_ml_tsh.py` with a small `--count` and short `--nsteps`, and confirm
a clean model load, written h5, hops firing, and zero amplitude NaN. Then scale up.

See also: `../data_manifests/DATA_MANIFEST.md`, `model_a_guide.md`, `model_b_usage_guide.md`,
`fssh_mlip_guide.md`, `fssh_pyseqm_guide.md`, and `stratified_split_guide.md`.
